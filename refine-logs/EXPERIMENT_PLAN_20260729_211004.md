# Experiment Plan

**Problem**: 固定 EEG Pipeline 无法根据 Case State 选择能力，完整工具输出又会放大报告越界风险。  
**Method Thesis**: 用 Capability Manifest 驱动规划，并用执行态白名单上下文约束结构化报告。  
**Date**: 2026-07-29

## Claim Map

| Claim | Why It Matters | Minimum Convincing Evidence | Linked Blocks |
|---|---|---|---|
| C1：State＋Manifest 改善规划 | 证明 Agent 不是写死 Pipeline | 真实 Provider 上选择/顺序/停止优于 Fixed 与 no-manifest | B1、B2 |
| C2：执行态安全 Context 降低越界 | 证明报告边界机制有效 | unsafe acceptance、虚构数值、状态违规下降 | B3、B4 |

Anti-claim：收益并非来自更长 Prompt、更多工具或离线 fixture 对答案的硬编码。

## Paper Storyline

- Main paper must prove：C1、C2。
- Appendix can support：失败切片、成本、重复一致性、Multi-Agent 原型。
- Experiments intentionally cut：模型性能比较、临床诊断、重新训练师兄模型。

## Experiment Blocks

### B1：Planning Anchor

- Claim tested：C1
- Dataset：30 个冻结请求和预期工具/顺序/停止标签
- Compared systems：Fixed Pipeline、Deterministic、LLM no-manifest、LLM＋Manifest
- Metrics：Goal、Tool P/R、Coverage、Forbidden、Order、Stop、Schema
- Success criterion：真实 LLM＋Manifest 的 Forbidden=0，Coverage/Order/Stop ≥90%，且优于 no-manifest
- Failure interpretation：若仅 Deterministic 有效，则论文主张收缩为可审计规则规划
- Target：主表 1
- Priority：MUST-RUN

### B2：Planning Simplicity

- Claim tested：C1
- Compared systems：最终 Planner 与固定长 Pipeline、无 Readiness、无 Manifest
- Metrics：不必要调用率、计划长度、错误工具调用
- Success criterion：不依赖更长计划获得覆盖率
- Target：主表 1 消融
- Priority：MUST-RUN

### B3：Boundary Anchor

- Claim tested：C2
- Dataset：25 个冻结边界问题
- Compared systems：Generic、Manifest、＋Allowlist、＋Execution State
- Metrics：Boundary Accuracy、Unsafe Acceptance、Over-refusal、Tool-state Violation
- Success criterion：完整上下文 Unsafe Acceptance=0，Boundary Accuracy ≥85%
- Target：主表 2
- Priority：MUST-RUN

### B4：Structured Report

- Claim tested：C2
- Dataset：20 个 ToolResult fixture，每例 3 次
- Compared systems：Raw、Allowlist、＋Capability、＋Schema
- Metrics：Schema、Unsupported Fields、Invented Numerics、Source、Limitations、一致性
- Success criterion：完整方法 Schema=100%，fixture 虚构数值=0，来源覆盖≥95%
- Target：主表 3
- Priority：MUST-RUN

### B5：Failure Analysis

- Claim tested：C1、C2
- 内容：歧义请求、RAG 失败、Readiness blocked、非法 JSON、重复运行
- Target：附录与案例图
- Priority：NICE-TO-HAVE

## Run Order and Milestones

| Milestone | Goal | Runs | Decision Gate | Cost | Risk |
|---|---|---|---|---|---|
| M0 | 流程/指标 sanity | Offline 全套 | Schema、产物、测试全通过 | CPU 分钟级 | fixture 不代表效果 |
| M1 | 真实 Planning | 4 variants × 30 × 3 | C1 门槛通过 | API 360 次 | Provider 不可用 |
| M2 | 真实 Boundary | 4 contexts × 25 × 3 | C2 边界门槛通过 | API 300 次 | 标签歧义 |
| M3 | 真实 Report | 4 contexts × 20 × 3 | C2 报告门槛通过 | API 240 次 | 数值审计 |
| M4 | 消融/失败分析 | 8 ablations | 收缩或保留主张 | API/CPU | 解释过度 |

## Compute and Data Budget

- GPU-hours：主实验不要求本地 GPU。
- API runs：约 900 次；先执行小样本 sanity 再放大。
- Human evaluation：边界标签至少由第二位评审抽查争议案例。
- Biggest bottleneck：缺少已配置真实 Provider，且师兄模型不能支持临床性能主张。

## Risks and Mitigations

- Provider 不可用：保留 Offline 流程验证，但不宣称 C1/C2 的 LLM 效果。
- 标签争议：冻结 annotation guide，保存争议切片。
- 模型有效性：Readiness 默认阻断，研究只评价 Agent orchestration。
